# Развертывание инфокиоска Windows

Ниже описан вариант **Multi-app kiosk**: пользователь может запускать только
разрешённые Edge и Throne, а остальные приложения Windows недоступны.
Поскольку Throne не работает как служба, его окно не получится гарантированно
сделать невидимым. Запускайте Throne до Edge и настройте в нём автоподключение
VPN; окно Throne должно оставаться свёрнутым или находиться за окном Edge.

## Подготовка приложения

1. Соберите frontend: `cd frontend && npm run build`.
2. Проверьте секреты и адреса API в `backend/.env`.
3. Установите Throne в постоянный путь, например
   `C:\Program Files\Throne\Throne.exe`. Не используйте путь внутри профиля
   администратора или папку Downloads.
4. Один раз войдите под отдельной стандартной учётной записью
   `KioskUser`, запустите Throne и настройте профиль VPN:
   - автоподключение;
   - переподключение при разрыве;
   - запуск вместе с Windows, если такая опция есть;
   - сворачивание после подключения.
5. Проверьте вручную, что `deploy\start_kiosk.bat` запускает backend и Edge.

## Какие приложения разрешить

В Multi-app kiosk добавьте только:

- Microsoft Edge (`msedge.exe`);
- Throne (`Throne.exe`);
- backend-процесс Python (`backend\venv\Scripts\python.exe`) или используйте
  отдельный запуск backend через Планировщик заданий.

Важный момент: backend не обязан быть доступен пользователю как приложение.
Практически надёжнее запускать его **до входа в kiosk-сеанс** через
Планировщик заданий с триггером `At startup` или через отдельный launcher.
В allowlist тогда достаточно Edge и Throne.

Команду запуска нужно выполнять от `KioskUser` после старта backend:

```bat
deploy\start_kiosk.bat
```

Если Edge должен открываться автоматически после входа, добавьте ярлык на этот
BAT-файл в автозапуск `KioskUser` либо настройте задачу `At log on`.

## Настройка Multi-app kiosk

На Windows Pro/Enterprise/Education создайте отдельную локальную учётную запись
`KioskUser` без прав администратора. Конфигурация Multi-app kiosk обычно
разворачивается через **Windows Configuration Designer**, Intune или Assigned
Access CSP. В профиле restricted user experience:

1. Выберите `KioskUser`.
2. Разрешите Microsoft Edge и Throne.
3. Спрячьте панель задач.
4. Запретите доступ к Settings, Control Panel, PowerShell, Command Prompt,
   Task Manager и Explorer.
5. Разрешите только нужные URI-схемы и сетевые настройки, если мастер их
   запрашивает.
6. Включите автоматический вход только для `KioskUser`, если устройство
   физически защищено и это соответствует политике колледжа.

Перед применением сохраните конфигурацию восстановления администратора.
Не тестируйте первый профиль на единственной административной учётной записи:
ошибка в allowlist может заблокировать обслуживание устройства.

## Сетевые доступы проекта

Assigned Access сам по себе не отключает исходящий интернет. Для проекта
должны работать следующие направления:

| Назначение | Адрес |
|---|---|
| Frontend и backend | `http://127.0.0.1:8000` |
| WebSocket чата | `ws://127.0.0.1:8000/api/ws/chat` |
| Gemini LLM/TTS | `https://generativelanguage.googleapis.com` |
| Yandex SpeechKit | `https://tts.api.cloud.yandex.net` |
| GigaChat | `https://ngw.devices.sberbank.ru`, `https://gigachat.devices.sberbank.ru` |
| Edge TTS, если включён | домены Microsoft Edge TTS |
| wttr.in | `https://wttr.in` |
| Расписание | домен из `frontend/src/config/kiosk.ts` |

Проверьте под `KioskUser`:

```powershell
Test-NetConnection 127.0.0.1 -Port 8000
Test-NetConnection generativelanguage.googleapis.com -Port 443
Test-NetConnection tts.api.cloud.yandex.net -Port 443
```

Не добавляйте API-ключи в allowlist, URL браузера или frontend. Они должны
оставаться только в `backend\.env`.

Погода получается через `wttr.in` без API-ключа. Frontend обращается только к
локальному адресу `/api/weather/current`, поэтому внешний сервис и его формат
не видны браузеру.

## Throne и VPN

Multi-app kiosk не запрещает сетевой стек Windows, поэтому VPN-туннель Throne
может обслуживать backend и браузер. Но проверьте в настройках Throne:

- не включён ли режим «блокировать LAN»;
- разрешён ли loopback/localhost;
- не блокируется ли Python;
- не требуется ли отдельное разрешение для DNS;
- не меняется ли маршрут к локальной сети.

После подключения VPN обязательно проверьте сначала localhost, затем внешние
API. Если `127.0.0.1:8000` перестал открываться, разрешите loopback в Throne
или добавьте исключение для Python/Edge. Не отключайте Kill Switch без
необходимости: лучше добавить точечные исключения.

## Обслуживание и выход администратора

Не делайте кнопку выхода с паролем частью frontend: это не защищает Windows.
Для обслуживания используйте отдельную администраторскую учётную запись.
Выйдите из kiosk-сеанса через `Ctrl+Alt+Delete`, войдите администратором,
измените конфигурацию Assigned Access и снова войдите как `KioskUser`.

### Запуск из административной учётной записи и переключение на киоск

Можно сначала войти администратором и запустить backend, frontend/Edge и
Throne, а затем выбрать **Сменить пользователя**, не выполняя выход из
административной учётной записи. В Windows при быстром переключении
пользователей процессы обычно продолжают работать в своей исходной сессии:

- backend продолжает слушать `127.0.0.1:8000`;
- Edge и Throne администратора остаются в административной сессии и не
  передаются пользователю `KioskUser`;
- Edge, запущенный в сессии `KioskUser`, может обращаться к backend через
  `http://127.0.0.1:8000`;
- исходящие запросы backend к Gemini, Yandex, GigaChat и другим API продолжают
  работать через общий сетевой стек Windows.

Это не то же самое, что выход из администратора. При **выходе из учётной
записи** Windows завершит обычные GUI-процессы этой сессии и backend, если он
не запущен как служба или отдельная задача, работающая независимо от входа.

Для Throne этот сценарий безопасен только если его VPN действительно создаёт
системный туннель/виртуальный адаптер или службу. Если Throne работает только
в интерактивной пользовательской сессии, после переключения он может:

- продолжать держать VPN;
- отключить VPN при блокировке или смене пользователя;
- требовать активного окна;
- не применять настройки VPN к сессии `KioskUser`.

Проверьте это до эксплуатации: после запуска Throne администратором
переключитесь на `KioskUser`, откройте `/health`, затем отправьте тестовый
запрос Gemini и синтезируйте тестовую фразу. Если VPN отключается, запускайте
Throne через его собственную службу или настройте его автозапуск отдельно под
`KioskUser`.

Важно: оставлять администратора просто заблокированным менее безопасно, чем
запускать backend и VPN как службы/задачи. Администраторская сессия остаётся
активной, поэтому обслуживание должно выполняться только на физически
защищённом устройстве, а для постоянной эксплуатации лучше использовать
отдельный стандартный профиль и независимый запуск backend.

Сначала протестируйте сценарий восстановления:

1. VPN недоступен — текстовая часть приложения продолжает работать.
2. Gemini/Yandex недоступны — появляется уведомление о профилактике озвучки.
3. Backend остановлен — Edge не должен показывать рабочий стол или другие
   приложения.
4. Throne переподключается — после восстановления API снова доступны.
